# 목적

하네스가 실제 소비자에서 안전하게 발견되고, 범용 규칙과 도메인 규칙이 중복·충돌하지 않는지 읽기 전용으로 확인한다.

# 절차

1. `<HARNESS_ROOT>/core/playbooks/harness-routing.md`와 대상 하네스 루트, 소비 프로젝트를 확인한다.
2. 현재 `core/`, `packs/`, `skills/`와 프로젝트 `AGENTS.md` 참조를 수집한다.
3. 오래된 `.ai/harness`, `.ai/nms-knowledge`, `.ai/skills` 경로와 존재하지 않는 경로를 찾는다.
4. Core에 도메인 사실이 들어갔는지, Pack에 범용 원칙이 복제됐는지 확인한다.
5. 중복 또는 모순되는 규칙, 여러 발견 위치의 같은 이름 스킬, 날짜가 지난 관찰 기록을 찾는다.
6. 민감정보 후보는 파일·행·분류만 기록하고 값은 출력하거나 복사하지 않는다.
7. 발견 사항을 위험도, 근거, 권장 조치, 미검증 범위로 보고한다.

# 규칙

- 이 스킬은 읽기 전용이다. 파일 이동, 삭제, 값 마스킹, 설정 수정은 명시 요청과 별도 변경 계획이 있을 때만 수행한다.
- 민감정보 후보의 실제 값은 터미널 출력, 실행 기록, 결과 보고에 남기지 않는다.
- 문서의 관찰 기록은 현재 source·로그·런타임과 다를 수 있으므로, 문서만으로 런타임 동작을 단정하지 않는다.
- legacy 경로를 발견해도 소비자 참조가 0건으로 확인되기 전에는 제거를 권장하지 않는다.

# 결과

- 검색 범위와 검색 명령을 기록한다.
- 각 발견 사항에 파일, 행, 범주, 영향, 후속 조치 상태를 남긴다.
- 검색하지 못한 프로젝트 또는 외부 문서는 미검증 범위로 명시한다.
