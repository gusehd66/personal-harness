# 목적

완료 주장 전에 산출물과 현재 소비자를 확인하고, 실행한 검증과 실행하지 못한 검증을 분리한다.

# 절차

1. 주 skill이 선언한 완료 기준, 변경 파일 또는 분석 산출물을 확인한다.
2. 현재 프로젝트의 test, build, browser, API, 로그, 수동 확인 중 산출물에 맞는 가장 작은 실제 검증을 선택한다.
3. 실행 결과와 실패를 원문 의미가 바뀌지 않게 기록한다.
4. 경로·소비자·설정 변경이 있으면 실제 참조가 유지되는지 확인한다.
5. 실행하지 못한 검증은 이유와 영향 범위를 함께 기록한다.
6. 결함이 발견되면 주 skill로 돌아가 수정한 뒤 다시 검증한다.

# 규칙

- 정적 검색이나 validator 통과를 browser, API, 제품 build, 운영 검증의 대체로 표현하지 않는다.
- 이 skill은 실제 제품 write, 장비 제어, DB 변경, 배포를 수행하지 않는다.
- 검증 도중 발견한 수정은 주 skill의 허용 범위와 승인 조건을 다시 따른다.
