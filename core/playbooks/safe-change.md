# 안전한 범용 변경 플레이북

## 사용 시점

코드, 설정, 문서, 자동화 설정을 변경할 때 현재 흐름을 확인하고 검증 근거를 남겨야 하는 경우 사용한다.

## 절차

1. 요청, 완료 기준, 허용된 변경 범위를 확인한다.
2. 현재 읽기·쓰기 경로, 실제 소비자, 활성 분기, 관련 기존 변경을 확인한다.
3. 작업을 경량 또는 전체 사이클로 분류한다.
4. 필요한 경우 프로젝트 `.harness/runs/`에 실행 기록을 만든다.
5. 기존 구조를 보존하는 가장 작은 변경을 적용한다.
6. 집중 테스트와 가능한 실제 표면 검증을 수행한다.
7. 실행한 검증, 실패, 미검증 범위를 구분해 기록한다.
8. 프로젝트·Core·도메인 Pack·스킬 중 승격할 지식이 있는지 판단한다.

## 실행 기록

전체 사이클은 `<PROJECT_ROOT>/.harness/runs/<YYYY-MM-DD>-<work-name>/` 아래에 다음 파일을 둔다.

- `PLAN.local.md`: 목표, 범위, 현재 흐름, 작업 순서, 완료 기준
- `EVIDENCE.local.md`: 실행 명령, 결과, 산출물, 미검증 범위
- `RETRO.local.md`: 실패 패턴, 유지할 기준, 지식 승격 후보

경량 작업은 `RETRO.local.md` 하나에 요청·변경 요약, 검증, 미검증, 반복 가능한 교훈 또는 `없음`만 기록한다.

실행 기록은 로컬 작업 이력이며 공식 사양이 아니다. 실패 기록은 자동 삭제하지 않는다.
