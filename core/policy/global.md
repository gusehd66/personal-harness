# 범용 AI 작업 정책

## 목적

모든 프로젝트에서 AI가 만드는 변경을 안전하고 작게 유지하며, 현재 동작을 근거로 리뷰 가능하게 만든다.

## 필수 작업 원칙

- 동작을 바꾸기 전에 현재 흐름과 실제 소비자를 먼저 확인한다.
- 요청 범위 안에서 가능한 가장 작은 변경을 우선한다.
- 사용자 변경과 무관한 dirty work는 보존한다.
- 기존 구조, 이름 규칙, 로그 방식, 오류 처리 방식을 존중한다.
- 명시 요청이 없으면 대규모 재작성과 추측성 리팩터링을 하지 않는다.
- 새 라이브러리와 새 도구는 실제 필요성이 확인될 때만 추가한다.
- 실행하지 않은 테스트, build, 브라우저, API 확인을 통과했다고 말하지 않는다.
- 실제로 수행한 검증과 미검증 범위를 결과에 분리해 기록한다.

## 변경 전 확인

- 읽기 경로: 값·상태·설정이 어디서 오는지
- 쓰기 경로: 값·상태·설정이 어디서 바뀌는지
- 실행 분기: 환경 설정, feature flag, 권한, 활성 구성
- 영향 범위: 호출자, 화면, API, 저장소, background process
- 현재 작업 범위 밖의 기존 변경: 보존할지와 충돌 여부

## 작업 종료 시 지식 분류

작업에서 얻은 사실을 다음 중 가장 작은 저장 표면으로 분류한다.

1. 한 번만 필요한 증거: 프로젝트 `.harness/runs/`
2. 프로젝트의 반복 규칙: 프로젝트 `AGENTS.md` 또는 `docs/`
3. 여러 프로젝트의 범용 원칙: `core/`
4. 특정 도메인에 재사용되는 지식: 해당 `packs/`
5. 독립적으로 반복 호출할 절차: `skills/`
6. 자주 변하는 사실: 실행 시 source, 로그, 공식 문서 또는 런타임에서 다시 확인

자동 승격은 하지 않는다. 근거와 영향 범위를 확인한 뒤 필요한 문서만 최소 수정한다.
