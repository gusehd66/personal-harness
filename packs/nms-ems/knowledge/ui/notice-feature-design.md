# 공지사항 UI 설계 기준

## 상태

- 2026-07-14 디자인 시안에서 선택된 방향이다.
- 실제 프런트엔드와 백엔드 구현 경로는 아직 확인하지 않았다.
- 구현 전 active site module, menu provider, authority filtering을 다시 확인해야 한다.

## 로그인 공지

- 로그인 성공 후 게시 중이며 `로그인 팝업 표시`가 활성화된 공지를 중앙 모달로 노출한다.
- 여러 건은 좌측 목록과 우측 상세 영역으로 나눈다.
- 중요 유형은 빨간색 배지, 읽지 않은 항목은 작은 초록색 점으로 구분한다.
- `오늘 하루 보지 않기`와 `닫기`를 하단에 제공한다.
- 하루 숨김 상태는 사용자, 브라우저, 날짜 범위를 명확히 정한 뒤 구현한다.

## 관리 화면

- `공지사항`은 좌측의 독립 메뉴로 제공한다.
- 관리 목록은 검색 조건과 단일 결과 테이블로 구성한다.
- 상태, 유형, 게시 기간, 검색어를 조회 조건으로 사용한다.
- 목록에서 게시 기간, 팝업 표시 여부, 게시 상태를 함께 확인한다.
- 등록, 수정, 삭제는 관리자 권한에만 노출한다.

## 등록 화면

- 유형, 제목, 게시 기간, 게시 상태, 로그인 팝업 표시, 내용, 첨부파일을 입력한다.
- 입력 폼과 로그인 팝업 미리보기를 좌우로 배치한다.
- `임시 저장`과 `등록`을 분리한다.
- 게시 기간, 필수 입력값, 첨부파일 크기를 등록 전에 검증한다.

## 구현 전 확인

- active site의 실제 menu/provider 등록 위치
- 로그인 완료 시점과 공지 조회 API 호출 위치
- `오늘 하루 보지 않기` 저장 위치와 다중 세션 처리
- 게시 기간 경계 시간과 서버/브라우저 시간대
- 관리자 authority와 일반 사용자 조회 권한
